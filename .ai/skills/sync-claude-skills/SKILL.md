## Purpose

XerahS keeps all AI assistant configuration under `.ai/` as the single,
IDE-agnostic source of truth (see `.ai/README.md`). Claude Code, however, only
auto-discovers skills from `.claude/skills/`, `~/.claude/skills/`, or plugins —
it does **not** scan `.ai/skills/`.

This skill bridges the two: it generates `.claude/skills/` **from**
`.ai/skills/` so every skill is natively discoverable by Claude Code (Skill
tool, `/slash` invocation, and automatic description-based triggering) without
forking content or breaking the single-source-of-truth model.

## Golden rule

`.ai/skills/` is authoritative. **`.claude/skills/` is a generated artifact —
never hand-edit it.** Edit the source under `.ai/skills/<slug>/`, then re-run
this skill. Each generated `SKILL.md` carries a `GENERATED by sync-claude-skills`
marker comment as a reminder.

## How to run

From the repo root, on Linux/macOS:

```bash
.ai/skills/sync-claude-skills/scripts/sync-claude-skills.sh
```

On Windows:

```powershell
.ai/skills/sync-claude-skills/scripts/sync-claude-skills.ps1
```

Add `--check` (bash) or `-Check` (PowerShell) to verify the mirror is current
without writing anything (used by CI). A non-zero exit means the mirror has
drifted and must be regenerated and committed.

## What the generator does

For each `.ai/skills/<slug>/`:

1. **`name` → `<slug>`.** Claude Code requires `name` to match `^[a-z0-9-]+$`
   and equal the directory name. Source skills whose `name:` uses spaces or
   capitals (e.g. "ShareX Core Standards") are normalized in the mirror only;
   the `.ai` source is left untouched so other IDEs keep their display names.
2. **`description` passthrough.** Copied verbatim (truncated to 1024 chars if a
   source ever exceeds the Claude Code limit).
3. **Frontmatter slimming.** Only `name` + `description` are emitted; undocumented
   keys (`metadata`, `tags`, `license`, ...) are dropped from the mirror.
4. **Resource copy.** Every other top-level file/dir is copied as-is — `scripts/`,
   `references/`, `assets/`, extra `*.md` — **except** `SKILL.md` (regenerated),
   `agents/` (other tools' agent configs), and `CLAUDE.md` (claude-mem stubs,
   not skill content).

The mirror is rebuilt from scratch each run, so deleting a source skill also
removes it from `.claude/skills/`.

## When to use

- After creating a new skill under `.ai/skills/`.
- After editing an existing skill's `SKILL.md`, scripts, or references.
- When Claude Code's Skill tool can't find a skill that exists in `.ai/skills/`.
- In CI / pre-commit, via `--check`, to prevent the mirror from drifting.

## Keeping it wired

- `.gitignore` ignores `.claude/*` but un-ignores `.claude/skills/` so the mirror
  is committed (zero-setup discovery on fresh clones).
- `.github/workflows/claude-skills-sync.yml` runs `--check` on every PR/push.
- Root `CLAUDE.md` documents that `.claude/skills/` is generated from `.ai/`.
